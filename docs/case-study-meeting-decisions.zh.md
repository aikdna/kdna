# 案例研究：四万美元的会议（说明性复合情景）

> **这是说明性复合情景，不是实测结果。** 本文用通用模式拼出一个教学用情景，
> 不是真实客户案例，也不是已复现的基准或已验证的商业成效。文中每个金额都是
> 情景设定，不是观测到的支出或节省；下文 Agent 的回答是示意/预期，不是实机
> 抓取的运行结果。

## 场景

一家 SaaS 公司的高管层开了一次产品方向会议。会上讨论了三个话题：

1. 是否进入企业市场
2. 当前产品架构是否需要重构
3. 下个季度的招聘优先级

会议持续了 90 分钟。有人提出想法，有人表达顾虑，有人表示支持。会议结束时，大家感觉"方向明确了"。

## 传统总结

一个没有 KDNA 的 Agent 收到会议记录后，预期会生成如下总结（示意）：

> 会议达成以下决策：
> 1. 启动企业市场探索
> 2. 重构认证模块
> 3. Q3 优先招聘后端工程师

这看起来高效、专业——但它是虚假的。

## KDNA 的判断

加载 `decision_state` KDNA 后，Agent 预期会逐一检查每个"决策"（示意）：

**话题 1：企业市场**

- 是否有人被指定负责？→ 否
- 是否有明确的时间节点？→ 否
- 是否有成功标准？→ 否
- 是否有人提出质疑但被搁置？→ 是（CFO 担心成本，但"后续再议"）

判断：**UNRESOLVED** — 有讨论，无决策。

**话题 2：架构重构**

- 是否指定了负责人？→ 是（CTO）
- 是否有时间节点？→ "Q3 前完成评估"
- 是否有明确范围？→ 有条件限制（"如果新方案性能达标就采用"）

判断：**CONDITIONAL** — 有条件决策。不应该被当作确定的行动计划。

**话题 3：招聘优先级**

- 是否指定了负责人？→ 是（HR 负责人）
- 是否有时间节点？→ 是（本周发 JD）
- 是否有明确选择？→ 是（后端优先于前端）

判断：**EXECUTABLE_DECISION** — 这个才是真正可执行的决策。

## 情景假设的成本

如果 Agent 把三个"决策"都当作确定的行动计划（情景假设，非实测）：

- 企业市场"决策"会产生大量准备工作和支出，但没有人真正负责推动
- 架构重构的"条件"会被忽略，团队开始执行一个还没有被验证可行的方案
- 招聘决策虽然正确，但与其他虚假决策混在一起，失去了优先级

情景设定的浪费：大约 4 万美元的人力成本和至少一个季度的方向混乱。这是
用来说明问题的假设值，不是观测到的损失，也不是可验证的节省。

## KDNA 的作用

KDNA 不改变会议的内容。它改变的是**Agent 对会议内容的理解方式**。

通过加载决策判断领域的公理和框架，Agent 学会：
- 区分讨论和决策
- 识别缺失的决策要素（负责人、时间、条件）
- 不在虚假的确定性上生成行动计划

这就是本案例要说明的 KDNA 作用：同样的输入，不同的判断方式。本案例是
说明性复合情景，其效果未经验证；在有/无 KDNA 的对照中，双方给出相同的
正确答案也是正常结果，不构成资产失败。
