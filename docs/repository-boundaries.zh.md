# 仓库边界——什么属于公开面

KDNA 的公开承诺面是**公开仓库**集合。本页说明该面覆盖什么、哪些保持私有，以及两者如何隔离。

## 公开仓库

本组织下的公开仓库构成公开承诺面：

- 协议与规范（`kdna`）
- CLI、Skills/MCP 适配器、Studio Core/CLI、Swift Core 与 Swift Studio 各包
- 公开资产发布仓与二进制 Work 发布通道（分发处于受控状态）

公开面上的一切文档、链接与版本——README、规范、已发布的 npm/PyPI 坐标、release 与网站——构成公开 API 与支持承诺。其中每个仓库的 README 各自说明其范围、支持版本与边界。

## 私有仓库

部分仓库为**私有**，涵盖如：

- 进行中的 Apple 生态应用集成工作，
- 商业与产品实验，
- 内部运营与协调。

对这些仓库：

- 其**名称与内容不公开**，也不在本页列出；
- 它们**不属于公开 API、文档或支持承诺**；
- 公开页面不链接它们——无法从公开文档到达的仓库，即不属于公开面。

私有不是质量评价。当所有者确认某仓库的内容、许可与文档达到公开标准时，可逐仓决定公开，并通过正常 release 通道公布。

## 内部白皮书工作仓

内部白皮书与判断系统工作仓**永久私有**，保存未发布草稿、内部记录与私人材料。工作仓本身不是发布面。由它产生的任何公开释放——白皮书 `.kdna` 资产，或经单独审阅的公开资产仓——都是逐项确认的独立发布决定。

## 边界如何维持

- 公开文档只链接公开仓库；
- 已发布包的元数据指向公开来源；
- 关于未发布或私有工作的问题，以实际已发布的内容回答，不引用私有材料。

另见[当前发布支持](./current-release-support.md)与 [FORK_POLICY](../FORK_POLICY.md)。
