# 为什么需要 KDNA

通用模型已经拥有广泛知识，也具备有用的默认判断。但模型的默认判断，不一定是使用它的个人、创作者、专业者、团队或组织自己的判断。

KDNA 的意义，是让判断可以被明确表达、跨模型携带，并通过一致的运行时契约被 Agent 使用。

## 判断资产合同

事实、Memory、Skill、Workflow、Policy、Prompt 和 Eval 都可能携带判断。它们
拥有不同的主要合同，但没有哪个系统垄断某一种内容。

KDNA 把以下判断内容作为一份资产的主要责任：

- 什么最重要；
- 哪些区别不能混淆；
- 什么风险应该阻止行动；
- 选择时遵循什么价值和取舍；
- 对这个作者或团队而言，什么才算做好；
- 这些判断在什么情况下不适用。

KDNA 不替代数据治理、Memory、私有计算、RAG、评测基础设施、微调、Skill、
Prompt、Policy 或 Workflow。同一判断可以继续存在于任何载体中。KDNA 增加的价值
不止一种：创作过程本身——把判断澄清、形成并表达出来——就是价值，发布它则让这套
标准可以被他人看见和取用；当判断需要独立身份、完整性、授权、加载和生命周期
合同时，KDNA 再增加一层价值。复用和加载不是唯一的价值来源。

## 谁的判断？

KDNA 不只属于企业，也不只属于获得认证的专家。

- 个人可以保存自己的偏好、价值、边界和选择方式；
- 创作者可以保存品味、表达标准和拒绝什么；
- 专业者可以封装诊断区别、风险阈值和取舍方法；
- 团队或组织可以把共同标准版本化，而不是把它锁进某个模型或应用；
- Agent 或工具也可以通过同一个公开协议创建 KDNA，作者身份不决定格式是否合法。

任何人都可以创建和发布 KDNA。KDNA Core 不判断其中的判断是否真实、正确、高级或有用。可选 Evidence 只描述一个资产已经观察到什么，不是创作许可证。

## 单资产与 Cluster

单个 KDNA 是原子、基础和默认路径：围绕一个清晰范围创建、校验、授权并加载一个判断资产。

KDNA Cluster 属于已发布的实验性高级面，正在产品重认证中；组合多个资产需要显式的 Host 策略和用户批准的候选集合。Cluster 不替代单资产模型，单资产路径也不会暗中调用 Cluster 路由。

## 开放创作，契约消费

开放协议不等于裸格式。创作方使用 KDNA 工具链创建并打包资产。当前源码消费者使用
公开的 Core admission 与 Read，并运行在独立可信的 Host provider 之下。已发布的
CLI 0.36.1 加载线则遵循：

```text
inspect → LoadPlan → authorization → load/project → Runtime Capsule → Agent
```

直接解压 ZIP、解码 CBOR 或读取原始 payload 是开发者审计路径，不是兼容的 Agent 消费路径。这条区分属于已发布加载线在 public、licensed 和 remote 三种访问方式下的合同；这些访问方式并不会让当前 Core/Read 具备加密准入能力。

## “可验证”验证什么？

每份实现只验证自己声明的版本合同。当前 Core admission 确立所捕获字节的技术有效性；它不认证来源，也不授予许可。已发布加载线包含它自己版本范围内的完整性、来源和授权检查。两者都不验证某种判断是真理，也不证明作者值得信任。消费者根据自己的情境决定使用什么资产和证据。
