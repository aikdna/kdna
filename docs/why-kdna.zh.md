# 为什么需要 KDNA

文字与排版有文档（`.md`、`.pdf`），数据与测算有电子表格，现场表达有幻灯片，互联信息有网页（HTML），确定性逻辑有代码。每一种重要的人类表达，最终都拥有了契合自身结构的文件形态。

唯独我们在长期实践中最看重的**思考、判断、取舍次序、适用边界与审美品味**，一直没有独立的文件载体。人们已经在用 AI 写作、规划、设计、写代码和做决策，但真正决定方向的核心判断，往往散落在长聊天记录、提示词、零散笔记和某个工具的上下文习惯里——换一次会话就可能丢掉推理前提，改了一处笔记另一处仍是旧口径，拿到结论的同事却看不到结论成立的限制条件。

当 AI 让文字、代码和方案等表面成品的生成越来越便宜，真正稀缺、真正决定结果差异的，恰恰是上游那套思考、判断与品味。KDNA（`.kdna`）因此把它们确立为一种可以独立保存、审阅、交付、采用并持续修订的**“作品”**。

## 回答可以很通顺，却悄悄抹掉真正的判断

通用大模型擅长生成四平八稳、普遍讨喜的回答。这种能力很有用，但当我们只让它“把内容改得更清楚”时，它常常在保持表面流畅的同时，把作者最关键的立场、取舍或适用边界悄悄磨平。

这里有一个来自发起人张零真实工作记录的具体例子：在《极简沟通》的训练方法里，“状态象限”原本用来观察**沟通对象**此刻的情绪与价值感；但在后来的一次任务里，Agent 完整保留了这张象限图，却把观察对象换成了**表达者自己**。图还是那张图，文字也很通顺，但判断真正盯住的对象已经变了。

这不是在宣称某种统计错误率，而是揭示一个普遍现象：**方法的外壳可以原样保留，核心判断对象却在不知不觉中被替换。** 一套真正立得住的判断，必须把“盯住谁、牺牲什么、到哪里停手”摆在明面上。

## 四个维度，让判断连成可维护的系统

| 核心追问 | 它把什么显式写清楚 |
| --- | --- |
| 你真正盯住的核心变量是什么？ | 不能被悄悄替换的观察对象、关键信号与问题焦点 |
| 冲突时先保什么、主动放弃什么？ | 当多个合理目标不可兼得时的价值排序与取舍代价 |
| 到哪里必须停下、交回给人？ | 自动推断或执行的边界条件、未知项与停手信号 |
| 遇到反例时怎样触发修订？ | 新证据、失误与例外如何推动具名版本演进，而不抹掉来龙去脉 |

这四部分彼此咬合：只有关注点而没有边界，就会过度外推；只有价值排序而听不见反例，就会变成教条；只有修改动作却找不到明确对象，留下的只是流水账，而不是判断。

## 独立的文件，让判断经得起审阅、流通与演进

KDNA 为可表达的判断与判断系统提供明确的身份、版本号、内在关联、必要前提与读取契约。在把判断交给任务之前，人可以先在 [KDNA Reader](https://aikdna.com/zh/reader) 中逐条读清它的主张与边界（首部公开判断作品《KDNA 白皮书》v1.0.0 可在 [aikdna.com/reader/?sample=kdna-whitepaper](https://aikdna.com/reader/?sample=kdna-whitepaper) 一键打开）；在实际采用时，兼容工具从目录出发，只读取与手头任务相关的判断，并完整保留它不可拆分的支撑前提与适用限制；作者也能把私密创作草稿留在本地，或用本地口令加密（`kdna protect`）保护核心作品，全程**永久无需注册任何在线账号**。

KDNA 的目的不是把一个人的一生装进容器，也不是“克隆人格”。同一个人完全可以为写作、产品评审、沟通教学分别维护边界清楚的不同作品。关键只在于：围绕某个具体领域，这套判断有没有讲清楚到足以被人读懂、讨论、选择采用并持续修订。

技术校验只是信任的一小部分：它能确认文件字节与容器结构符合规范，却不能替你证明一条判断是正确的、高水准的或适合当前处境的——那永远需要阅读内容、核对证据，并在关键处由人做出决断。

如果一篇普通 Markdown 文档、几句提示词或现有的代码仓流程已经能很好地满足需求，请继续使用它。只有当判断的身份、配套前提、人眼审阅、版本对比与跨工具协作真正需要一种共同形态时，再考虑 `.kdna`。
